# ADR-002: Политика защиты от утечек (Fail-Closed Kill Switch)

- **Статус:** Принято
- **Контекст:** Пользователь подтвердил требование: настраиваемый Kill Switch с режимом `fail-closed` по умолчанию.

## Решение

1. **Активный VPN + здоровый роутер:** Любой пакет выбранного VPN-приложения, который не удалось корректно пробросить (SNAT/инжекция) в Wintun, жёстко отбрасывается (`drop`), никогда не возвращаясь на физический адаптер.
2. **Обрыв, отключение или переподключение VPN:** При `kill_switch == fail_closed` user-mode WFP немедленно устанавливает `FWP_ACTION_BLOCK` на `FWPM_LAYER_ALE_AUTH_CONNECT_V4/V6` для всех `ALE_APP_ID` из VPN-списка (кроме loopback и LUID Wintun).
3. **IPv4-only туннель:** Для VPN-приложений всегда блокируется прямой IPv6 (`ALE_AUTH_CONNECT_V6`), чтобы исключить утечку реального IPv6.

## Честное ограничение при аварийном краше (`SIGKILL`)
- При `FWPM_SESSION_FLAG_DYNAMIC` Windows автоматически удалит WFP-фильтры после падения `pwdtt.exe`. Интернет не сломается, но выбранные приложения смогут уйти напрямую.
- При персистентном подслое (опция «Строгая защита после краша») блокировка сохранится после падения процесса до повторного старта PWDTT (который очищает старые фильтры по Provider GUID) или запуска утилиты `pwdtt-reset-wfp`.
